# Public HTTPS Deployment

The Android app expects the dashboard/backend at a public HTTPS URL. Render or Railway are the best fit for the current Node server because OTP challenges and sessions are kept in memory during this stage.

## Render

This repo includes `render.yaml`.

1. Push the project to GitHub.
2. In Render, create a new Blueprint from the repo.
3. Render will create a web service named `marketpulse-pro`.
4. Set environment variables:

```text
RESEND_API_KEY=your_resend_key
FROM_EMAIL=onboarding@resend.dev
NODE_ENV=production
```

`SESSION_SECRET` is generated by the blueprint. If you create the service manually, set it to a long random secret.

Expected URL if the service name is available:

```text
https://marketpulse-pro.onrender.com/
```

If Render assigns a different URL, update Android with:

```bash
cd android/MarketPulseProAndroid
gradle assembleDebug -PdashboardUrl=https://your-render-url.onrender.com/
```

or replace the default in `app/build.gradle`.

## Railway

This repo includes `railway.json`.

1. Create a Railway project from the repo.
2. Set environment variables:

```text
RESEND_API_KEY=your_resend_key
FROM_EMAIL=onboarding@resend.dev
SESSION_SECRET=long_random_secret
NODE_ENV=production
```

3. Generate a public domain in Railway.
4. Build Android with:

```bash
cd android/MarketPulseProAndroid
gradle assembleDebug -PdashboardUrl=https://your-railway-domain.up.railway.app/
```

## Health Check

The server exposes:

```text
GET /healthz
```

Expected response:

```json
{"status":"ok"}
```

## OTP/Auth Requirements

- `POST /api/auth/send-otp`
- `POST /api/auth/verify-otp`
- `GET /api/auth/me`
- `POST /api/auth/logout`

When `NODE_ENV=production`, session cookies include `Secure`, `HttpOnly`, `SameSite=Strict`, and `Path=/`.

## Important Limitation

The current OTP/session store is in memory. It works for one hosted Node instance, but production should move OTP challenges and sessions to Redis or a database before scaling horizontally or using serverless platforms.
